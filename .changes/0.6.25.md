## 0.6.25 - 2026-09-03
### Added
* Exact-money primitive (#FIN5): lib.money server-side and gina.money in the browser bundle — ISO 4217 minor-unit integer arithmetic on BigInt, with an in-lib exponent table (JPY 0, BHD 3, CLF 4, default 2). Strict wire-string parse() rejects float inputs and excess fractional precision (rounding stays the application's decision); add/subtract/compare/multiply throw on currency mismatch and integer-factor violations; format() renders the canonical wire string with exactly the currency's fraction digits; toMinor()/fromMinor() round-trip JSON-safe minor-unit counts. Amounts stay exact beyond Number.MAX_SAFE_INTEGER minor units. Display formatting deliberately stays with the i18n layer (Intl.NumberFormat). The module is dependency-free and dual-published; changes to it ride the browser bundle (pickup: restart and re-bake).
* isIban and isBic FormValidator rules (#FIN4): IBAN validation per ISO 13616 - shape, official per-country length for 87 registered countries, and the ISO 7064 MOD 97-10 checksum - with a tolerant read (case and space/hyphen separators are normalized for validation only; the stored value is never mutated, and unknown country codes pass on shape + checksum), plus BIC validation per ISO 9362 (8- or 11-character shape, case-insensitive). Shared client + server like every FormValidator rule; empty values stay adjudicated by isRequired alone.
* Idempotency keys (#FIN6): opt-in Idempotency-Key request deduplication at the router band, per the IETF draft. Arm it with settings.json server.idempotency (a declared kv namespace + keyField) and opt routes in with routing.json top-level idempotency true (or required true to answer 400 when the header is missing). The first request bearing a key reserves the operation and executes; its rendered JSON response is recorded, and a retry with the same key and payload is answered with the recorded response plus Idempotency-Replayed true. A duplicate while the original is in flight gets 409 + Retry-After; the same key with a different payload gets 422. Anonymous callers are skipped (a stored response never crosses principals), 5xx and oversize responses release the reservation so retries re-execute, and the dedup scope follows the kv namespace backend (memory per process, redis/sqlite replica-shared).
* XML request handling (#FIN1): application/xml, text/xml and application/*+xml request bodies now reach the application verbatim on POST, PUT and PATCH instead of being run through the form-encoded decode path. request.body keeps the exact document the client sent (the same string request.rawBody carries) and the application parses it with the XML library of its choice — the framework never parses XML itself, so it takes on no XML parser surface. Previously such a body was silently destroyed rather than rejected: the form decoder splits on & and then on =, keeping only the first pair, so the XML declaration alone collapsed a whole document to one bogus key, and that object then replaced request.body. The matched set follows the convention ASP.NET Core, Spring and type-is share — the +xml structured-suffix wildcard is scoped to application/, so image/svg+xml is not matched, and the RFC 7303 types that are not XML documents (application/xml-dtd and both xml-external-parsed-entity forms) are excluded. urlencoded, JSON and multipart bodies are unaffected, and the same single chokepoint serves both engines.
* renderXML delegate (#FIN2): first-class XML responses, the outbound counterpart to verbatim XML request handling. Call self.renderXML(xmlContent) from a controller action to send a pre-serialised document — gina does not build XML any more than it parses it, so you serialise with the library of your choice and the delegate owns the wire concerns. The content type defaults to application/xml (RFC 7303 recommends it over text/xml) with the charset taken from the bundle encoding, and an optional second argument covers the suffix family: self.renderXML(doc, "application/soap+xml"), atom+xml for a feed, or a vendor tree. The status code comes from response.statusCode rather than the payload — an XML string has no envelope for the renderJSON status convention — so set it upstream or answer errors with self.throwError(). HEAD requests get the headers including a byte-accurate content-length with no body, HTTP/2 responses carry the status as a pseudo-header with upstream headers folded into the frame, and opt-in HTTP/2 trailers work as they do for every other delegate. A route using idempotency keys records its response envelope here too, so a retried XML mutation replays rather than re-executing.
* Message-schema validation seam (#FIN3): routes can now run the raw request body through an application-supplied validator before the controller action. Declare param.messageValidator: "<name>" on a route and ship a factory module at message-validators/<name>.js — the factory runs once at bundle boot (compile your XSD or open your sidecar pool there; a broken module refuses the boot instead of silently skipping validation), and the returned validate(document, req) function — sync or async — receives the verbatim body string on every matching request. Return { valid: true } to proceed, or { valid: false, status, errors } to refuse: 422 by default (schema-invalid, with your errors array forwarded on the response body), 400 for a document that does not parse at all, or 503 with an optional retryAfter when the checker itself is unavailable. A thrown error fails closed as a 500 — a request never proceeds unvalidated. The framework ships no schema engine and takes on no XML or JSON-Schema parser surface: the validator is yours (an XSD library, a Schematron sidecar, a JSON-Schema engine), the hook, ordering and refusal shape are gina's. The gate runs after authorization, rate limiting and idempotency, and before DTO field validation; routes without the declaration are byte-identical.
### Fixed
* Client-side routing helper no longer swallows its own "route not found inside your view" diagnostic: when a rendered 404 marker or an alternate-route lookup identifies a route missing from the running table, the composed message is now emitted via console.warn on the first sighting of each route (the gina.notFound registry still dedups repeats), and the alternate-route arm now records its registry entry so repeat counts accumulate instead of resetting. Server-side miss logging is unchanged. (#B462)
* The query() basic-auth option is now honoured on HTTP/2 — and can no longer leak. `options.auth` ("user:password") was consumed by node's own request() on HTTP/1.x only; on the HTTP/2 path the option-copy loop forwarded it into the outgoing header block as a literal `auth:` header (the strip set did not list it) and no `Authorization` header was ever minted, so the credential travelled in a nonstandard header while authentication silently never happened. The option is now minted into `Authorization: Basic <base64>` before dispatch on BOTH transports through one code path — a caller-supplied authorization header always wins, matching node's HTTP/1.x behaviour — and the option itself is deleted pre-dispatch (and listed in the HTTP/2 strip set as a belt), so an empty or malformed credential cannot travel as a header either. If anything downstream relied on receiving the literal `auth:` header on HTTP/2, that was the defect, not a contract. (#B465)
### Security
* Server-side data serialised into the Inspector's inline `<script>` blocks can no longer be read as template source by the swig renderer. The `__ginaData` and `__ginaLogs` scripts are spliced into the layout before it is compiled (their per-request nonce is a swig conditional), which left every swig delimiter live inside the serialised page data: a stored value such as `A{{ 7*7 }}B` rendered as `A49B`, and a `{% %}` tag inside a value executed with the page's locals in scope. The shared inline-script helper now also escapes `{` and `}` inside JSON string literals (`\u007b` / `\u007d` are valid JSON escapes, so every value still parses back identical); structural braces are untouched. Same reachability as the 0.6.23 hardening: only pages that emit the Inspector block (development by default, production only when `displayInspector` is enabled). The nunjucks renderer injects after rendering and was not affected. Server-side only: pick it up with a bundle restart, no rebuild needed. Internal reference #B463.
