## 0.5.14 - 2026-07-09
### Added
* Stable publishes now assert README.md carries exactly one "What's in <version>" section, naming the version being released (script/check_readme_freshness.js, wired into the release prepare step). The publish aborts when the section is missing, duplicated, or names a different version. Previously the gate only asserted that README.md had been touched since the previous stable tag, which is blind to a wrong edit: adding a new section while leaving the prior one in place touches the file, so the gate passed while shipping a README whose newest release was buried under older ones. The version-match assertion is skipped on prerelease targets, where the drafted stable heading legitimately precedes the version bump. Alpha publishes skip the gate entirely.
### Fixed
* A form error label that is not a string no longer takes the form down. The validator engine now discards it, warns once naming the rule, and renders that rule's English default instead — covering all four sources a label can arrive from: a bundle catalog's `_validator` node, a `gina.validator.setErrorLabels()` override, a rule's `errorMessage` argument, and a field's `error`. Only the first was caught by the boot lint. Previously the engine threw `TypeError: target.match is not a function`, and nothing on the path catches it: the validation pass aborted, so no error message rendered, the form never submitted through gina, and because the boot-time pass throws out of an unguarded form-binding loop, every later form on the page was left unbound — the page silently fell back to native browser submits with no client-side validation at all. Separately, `compileError()` no longer throws when a backend field error carries no `{{placeholder}}` (a plain string such as "Already taken" made `String.match` return `null`, and the null was dereferenced), and the query rule keeps its resolved label when a backend field error is not a string.
* A validation error returned for a specific form field no longer exposes a raw server stack trace to the browser. When an ApiError is built for a client field (`new gina.ApiError(err, 'fieldName')`) and the underlying error has no message — so the framework falls back to its stack — or an application passes a stack string directly, the field message is now replaced with a neutral one (`An error occurred`) outside local scope; the full stack is kept in local scope for debugging. This mirrors how Gina already strips the stack from the JSON error body outside local scope, and closes the one channel that strip could not reach: the per-field message map, which the form validator renders verbatim.
* A validator field that stays in error while its message changes — because the value now fails a different rule, the message is value-dependent, or a late `setErrorLabels()` overlay changed the label — now re-announces the new message through the form's ARIA live region, so assistive technology no longer keeps announcing the first message. The visible message already refreshed on such updates; this fixes the screen-reader announcement to match.
