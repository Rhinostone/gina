## 0.6.27 - 2026-09-05
### Changed
* Two controller events fire less often now that the fluent `{onComplete}` handles deliver per call (#B475). `query#complete` is emitted on the controller only when nothing consumed the outcome — no callback and no `.onComplete()` — one tick after settlement; a fluent query that registers a callback no longer emits it (no in-tree or documented listener existed). `'uploaded'` is no longer emitted for the fluent `store(target).onComplete(cb)` form (never a documented `@fires`; the callback form never emitted it). Also, `query()` in callback form now returns `undefined` on every path instead of an unusable per-transport handle object on success, and an explicit `null` callback selects the fluent form instead of throwing `callback is not a function` at delivery time.
### Fixed
* `lib.archiver.compress()` no longer drops the first entry of the top-level directory in its directory form. The walk seeded its work list from index 1 — the author evidently expected `.` to come first, which node's `readdir` never returns — so a directory holding a single file archived to an empty zip, and every directory-form archive silently lacked one file. The in-tree `project:backup` command uses the array form and was never affected; only direct callers of the directory form are. No configuration change; pickup is a bundle restart.
* `lib.archiver` now settles each `compress()` and `decompress()` call on its own completion channel. Every completion used to be signalled by emitting one fixed event name on the process-wide singleton, so two overlapping calls in one process — two queue consumers, or a request handler beside a worker — both received whichever run finished first: the second caller was released early with the first run's archive path, and its own archive was left at 0 bytes; the array form also kept its output stream in an implicit global, so finishing one run closed another's stream. Each call now settles exactly once for its own `onComplete` listeners and trailing callback, a listener attached after the run has already settled is still delivered, and the documented `archiver-<method>#complete` event is still emitted on the singleton for observers. Errors on the streams the lib opens itself are now delivered to the caller too: an unreadable input used to either crash the process on an unhandled stream error or hang the run forever — leaving a corrupt partial archive on disk — depending on timing, and an unwritable target crashed both the array and directory forms; all of them now reach `onComplete` as the stream's error. The synchronous error paths (a missing source, a source that is neither a file nor a directory) reach `onComplete` instead of firing before the handle is returned, and both promisify shapes work — a trailing callback with options lacking `method`, and `compress(src, target, cb)` with options omitted. The same restructure incidentally closes a hang in the trailing-callback form: `compress()` registered its completion listener from `options.method` before the option defaults were merged, so a caller that did not set `method` explicitly — the documented promisify shape with default options — waited on `archiver-undefined#complete` while the run emitted `archiver-gzip#complete`, and its callback never fired. The fluent handle form was never affected, because it is built after the merge. No configuration change; server-side only, pickup is a bundle restart.
* The single-file form of `lib.archiver.compress()` now writes a real one-entry zip, and `decompress()` reads every form back. It used to pipe the file through a gzip codec and write the result under the `.zip` name, which `unzip` and `decompress()` both rejected, and `method: 'br'` or `'deflate'` were accepted by the option validator and silently produced that same gzip. The archive keeps its path — `<target>/<name>.zip`, with `<name>` defaulting to the file's basename — and holds one entry named by the basename; the bytes change from a gzip member to a DEFLATE zip, so anything that gunzipped the output directly must switch to reading it as a zip. `method` is now validated against `gzip` alone (the value names the `archiver-gzip#complete` completion event and has never selected a codec for the array or directory forms), so `br` and `deflate` throw synchronously, as they did before a refactor silenced them. The same branch also skipped any input whose path carried a dot-prefixed segment — a `.env`, or a file under `~/.config/` — reporting success with the INPUT path as the archive, leaving an empty `<name>.zip` on disk and leaking the read and write descriptors it had opened; such a file now archives like any other, as the directory form already did. A missing input still settles the `file not found` error. Server-side only; pickup is a bundle restart.
* FormValidator now reacts to a browser or password-manager autofill (#B478). A fill lands without any keystroke, and on Chrome without an input or change event until a later gesture, so the live check never re-ran: the submit control kept the gated look it was given at bind time on a form the user could see was complete, and an autofilled invalid value showed no error. The default stylesheet now gives every autofilled control a 1ms keyframe named gina-autofill-start, and the validator routes the resulting animationstart into the field's own live check: a readable value is validated like a typed one (the gate opens, or the field shows its error), while a value the browser still withholds from script (Chrome, until the first gesture) no longer counts against the gate and renders no false required error. The submit-time check is unchanged, so a value still withheld at click time is refused and never posted empty. Browser-bundled: rebuild each consuming bundle to pick it up.
* The fluent `{onComplete}` handles of `self.query()` and `self.store()` now deliver to their own call (#B475). Both registered the application callback on the controller instance's shared EventEmitter: `store(target).onComplete(cb)` used `self.on('uploaded', cb)` and never removed it, so a second `store()` on the same controller — sequential or overlapping — re-invoked every earlier callback with the later result, and `query(options, data).onComplete(cb)` cleared every `query#complete` listener before registering its own, so a concurrent fluent query on the same controller evicted the first one: its callback never fired, the survivor could receive the other call's payload, and the evicted response was emitted to nobody — on both transports, with no log line. The synchronous failure paths of `query()` (missing host, open circuit, unreadable CA, the outer catch) also returned `emit()`'s boolean instead of the handle, so chaining `.onComplete` threw `TypeError` and the error was lost. `query()` now mints one delivery channel per call whenever no callback (or `null`) is given and returns the handle on every path: registrations chain (`onComplete()` returns the handle), every registration fires, a registration made after the call settled fires on the next tick, a synchronous failure reaches `cb(err)` on the next tick, delivery rides the callback path so every guard and every retry carries the channel, and fluent queries gain the circuit breaker's outcome recording. The delivered shapes are unchanged: `cb(false, data)` on success, `cb(data)` for a known non-2xx status, and the `{status, error}` wrap for a transport or pre-transport failure. `store()`'s handle now calls `start(target, files, cb)` directly, with the same arguments and the same synchronous timing as before. Server-side only; pickup is a bundle restart.
* FormValidator now tells the truth about a field the browser autofilled but still withholds from script at submit time (#B341). Such a field is visibly filled yet reads empty to script, so the submit-time check correctly refuses to post it, but the message it rendered was the plain required label, a problem the user could not see. The engine now consults a new built-in label key, isRequiredAutofill (default: Filled in by your browser: click the field to confirm it), for that one case, keeps the verdict, the errors key and the submit gate unchanged, and marks the control with data-gina-form-autofill-withheld="true" as a styling hook, set through the dataset API (dataset.ginaFormAutofillWithheld), so the hyphenated attribute name is never a literal in the minified bundle: check for the marker on the DOM element, not by grepping the bundle. The key is alias-filled from an app-supplied isRequired label, so a localized catalog keeps its own required wording until it translates isRequiredAutofill itself. The withheld predicate is exposed as gina.validator.isAutofillValueWithheld. Browser-bundled: rebuild each consuming bundle to pick it up.
* `self.query()` issued while the controller is rendering from another required controller (a `renderingStack` deeper than one frame, which `requireController` produces because the required controller shares the caller's options object) returned the literal `false` and delivered nothing: the callback form never fired and the fluent `query(...).onComplete(cb)` chain threw `TypeError`. The refused query now settles like every other synchronous failure: the callback receives an `Error` whose `code` is `NESTED_RENDER` (in-line in the callback form; on the next tick through the handle, wrapped as `{status: 500, error}`), the handle comes back on that path too, and the upstream is still never contacted (#B479)
### Security
* Inspector payloads no longer leak across requests through the compiled-template cache (#B464). With server.cache.enable true and the Inspector block injected (automatic in dev; in production only when a controller calls self.render(data, true)), the window.__ginaData script was baked into the layout BEFORE swig compiled it, so the per-view compiled template and the persisted .gina-layout-cache file carried the FIRST request's page data (the controller's data, the session card, the environment) and served it to every later request of that view, to other views compiled after it, and to every later process until the file was removed; the popin hidden inputs gina-without-layout-xhr-data / -view were a second pre-compile carrier, and /_gina/reveal plus the Inspector stream froze with them. The compiled layout now carries only an HTML-comment marker: both cache paths build the payload after the template executes and splice this request's script (or drop the marker when the Inspector is not wanted), so a cache hit refreshes the Inspector sinks too; the hidden inputs are spliced after execution under the same gates; and a stale layout-cache file written by an earlier release is healed in place on the next compile. Server-side: restart each bundle to pick it up; deleting .gina-layout-cache under the bundle templates root is optional, never required.
