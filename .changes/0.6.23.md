## 0.6.23 - 2026-09-02
### Added
* Security headers are now emitted by the framework itself, on both engines, via `settings.json > server.securityHeaders` (OWASP A02). This closes a gap that made the existing `#HDR` plugins unreachable for most projects: they are Express middleware, and the default `isaac` engine never runs the Express middleware chain for HTTP responses, so mounting the `SecurityHeaders()` orchestrator emitted nothing at all there. Seven headers are on by default, chosen because none can break a working application — `x-content-type-options`, `x-download-options`, `x-permitted-cross-domain-policies`, `x-xss-protection`, `referrer-policy`, `x-dns-prefetch-control` and `origin-agent-cluster`. Four are opt-in behind a single key each, because each breaks a legitimate deployment: `xFrameOptions` (cross-origin embedding), `coop` (severs `window.opener`, so OAuth and payment popups), `corp` (cross-origin asset loading) and `hsts` (a 180-day HTTPS commitment, emitted over plain HTTP too). Precedence is first-writer-wins, so a mounted plugin, an `env.json > server.response.header` entry or an upstream proxy always wins. `coop` and `corp` are never applied to `/_gina/*`, which is deliberately cross-origin. Set `server.securityHeaders.enabled` to `false` to restore the previous behaviour (#OW1)
* `settings.json > server.maxBodySize` bounds non-multipart request bodies, which previously accumulated with no ceiling at all — a single large body was an unbounded-memory exposure (OWASP A10). A body past the limit is answered 413 and the stream is destroyed. The default `64MB` is deliberately permissive: the ceiling exists to stop unbounded growth, not to police payload shapes, and gina's own inter-bundle `self.query()` hop posts through the same pipeline. A companion `server.maxBodySizeWarn` (default `2MB`) only logs, so you can measure your real distribution before choosing a stricter ceiling. Both accept B/KB/MB/GB (a bare number means MB); `0` disables either. Multipart uploads are unaffected — they remain capped by `upload.maxFieldsSize`. `server.timeout` is now configurable too, and stays `0` (unlimited) by default on purpose: a finite whole-request clock would kill Server-Sent Events and WebSocket connections, and the slow-body case it would otherwise cover is already closed by the body cap (#OW2)
* Opt-in Subresource Integrity for the asset tags gina emits: set `"sriEnabled": true` in `templates.json > "_common"` and every same-origin `<script>` and `<link rel="stylesheet">` whose file resolves on disk gains `integrity="sha384-..."` plus `crossorigin="anonymous"`, so a tampered or truncated asset is refused by the browser instead of executed. Fail-open by design: external URLs, unresolvable paths and unreadable files simply get no attribute — a wrong hash would hard-block the asset, so nothing is ever guessed. Hashes are cached per file and re-validated by mtime and size on every render, which means a rebuilt asset gets a fresh hash with no restart. Two operational notes: pages already stored by the render/output cache keep the hash they were rendered with, so flush that cache after rebuilding assets; and the HTTP/2 preload hint is suppressed for integrity-checked assets, since a hint carries no integrity metadata and a mismatched preload would be a wasted double fetch (#OW3)
### Changed
* `settings.json > server.hidePoweredBy` now defaults to `true`, so the framework no longer advertises its name and exact version on every response. A version banner is free reconnaissance for an attacker and buys the operator nothing. Set it back to `false` to restore the previous behaviour. One interaction worth knowing: with the render/output cache enabled and `server.cache.name` unset, the new default raises the existing boot warning about the cache still naming the framework on the wire via `Cache-Status` — set any token there to close that disclosure too (#OW1)
### Fixed
* A JSON body carrying a nested object whose own `constructor` key holds a primitive, null, array or plain object no longer crashes the merge: the plain-object check read `.prototype` off the shadowed value eagerly and threw `Cannot convert undefined or null to object` — request-reachable through PUT bodies and pre-existing (measured identical on 0.6.21). The check now computes lazily with the read guarded, a 24-shape differential sweep pins identical answers on every previously non-crashing input, the guarded key is still dropped per the 0.6.22 disclosure and sibling fields survive (#B450)
### Security
* Hardened the escaping of server-side data serialised into inline `<script>` blocks. The previous guard matched only the literal `</script>` and `<!--` sequences, but the HTML5 script-data end tag also accepts a tab, newline, form feed, space or `/` after the tag name, so `</script >` and `</script/>` closed the block and the remainder of a stored value was parsed as HTML. Values are now escaped by neutralising `<` itself, which no terminator spelling can work around, and the same helper is applied at every site that serialises server data into an inline script rather than at one site per renderer. U+2028 and U+2029 are escaped as well, since both are legal in JSON but were line terminators to the JavaScript parser. The escaped output parses back to an identical value, so no data shape changes. Reported as #69. Server-side only: a bundle restart picks this up, no rebuild needed.
