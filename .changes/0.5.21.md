## 0.5.21 - 2026-07-20
### Added
* Popin eager preload — a trigger can opt into warming its AJAX content off the critical path with data-gina-dialog-preload="eager" (case-insensitive): after window load, at browser idle, the popin plugin fetches the content one trigger at a time through the same gate as the hover/focus warm (the "false" opt-out, the disabled skip, and the cache dedup all apply — whichever warm runs second is a no-op), so a later open injects instantly with no second GET. The pass is skipped when the browser signals Save-Data. Default behavior is unchanged: hover/focus warm stays the default and "false" still disables warming entirely. Browser-bundled — rebuild your bundles to pick it up.
### Fixed
* Fixed CSP useNonce nonces diverging between the Content-Security-Policy header and the framework-injected inline bootstrap script on cache-enabled routes: the bootstrap nonce was frozen at first compile inside the per-view compiled-template cache (and the persisted layout cache) while the header rotated per request, so every cache-path response failed nonce validation under an enforcing policy. The bootstrap nonce is now injected as a render-time template conditional (re-evaluated per response), stale pre-fix layout-cache files are healed in place on the next compile, and cache HITS re-mint: the serve path rewrites the stored CSP header and body with a fresh per-response nonce on both engines, so header and markup nonces match and rotate on misses and hits alike.
* A bundle whose config/routing.json is missing or unreadable at boot now refuses to start with an error naming the bundle and environment (previously it booted silently with only the framework-synthetic routes, so every app route 404'd and cross-bundle route lookups threw hours later with no boot-time signal); an external supervisor restart (an orchestrator liveness/restart or a container restart policy) then retries until the release tree settles, which self-heals mid-deploy races — the gina daemon itself does not retry a startup crash (it reports it once and stops; restart manually) — a deployment that relied on the silent half-boot must fix its release artifact. The route-lookup not-found error now also names the bundle and its rule count, so a degraded or near-empty routing table is tellable from a plain mistyped rule at the call site
* FormValidator: on live-check fields with autocomplete="off", the Safari-autocomplete keydown interception no longer swallows modifier chords — Cmd/Ctrl+A/C/V/X/Z and Cmd+Arrow run their native defaults instead of typing the chord letter into the field (Cmd+A appended "a") or routing keyboard paste through document.execCommand("paste"), which is inert in unprivileged web content, so keyboard paste on intercepted fields works again (#B134)
* The framework env template no longer declares a hardcoded accept-language RESPONSE header — Accept-Language is a request header, and the runtime-merged template default made every response (error responses included) emit it. A project or bundle env.json that declares its own response headers keeps working, including re-declaring accept-language, which is still emitted verbatim and still honored by the controller's locale fallback; deployments whose generated env.json copied the old template value should remove that line themselves
* FormValidator: the Safari-autocomplete keydown interception (fields with autocomplete="off" on a live-check form) now gates on REAL Safari only — every Chromium UA (Chrome/Edge/Brave/Opera) carries the Safari/537.36 token, so the bare /safari/i test ran the WebKit workaround on Chromium where it was never intended; Chromium users get native typing/autofill behavior back, while WebKit-on-iOS browsers (CriOS/FxiOS) stay covered by design (#B135)
* FormValidator live-check: when the whole-form validation pass turns valid (e.g. a checkbox interaction raises a field another field's comparison rule reads), the pass now clears every previously-errored field's rendered error message along with re-enabling the submit trigger — pre-fix the stale blocking-error paragraph stayed visible next to an enabled submit until the field's next keystroke; applied to both global-pass copies (input/checkbox/radio path and select path), and the pass still never renders new errors on untouched fields (#B136)
* Merged-process projects (several bundles sharing one port, served by one process): the first cross-bundle getUrl no longer permanently replaces the target bundle's routing table with the starting app's — previously every cross-bundle link to that bundle rendered the literal 404:[<METHOD>]<rule>@<bundle> marker instead of a URL, and merged-mode inbound statics dispatch could match requests against the wrong bundle's table. Each bundle now keeps its own routing table (the hostname share is preserved); projects with distinct per-bundle ports were never affected.
### Security
* Server-side error responses no longer serialize stack traces to HTTP clients outside local scope: the engine-level error responder logs the full stack server-side and sends the message line only (JSON/XHR bodies, the inline HTML fallback, and custom-error-page data), the JSON render delegate's HTTP/1.1 reason-phrase fallback ships the error message instead of a stack, and the cached-file stream error path ships message-only — local scope keeps the stack on the wire for the development toolbar
