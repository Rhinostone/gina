## 0.6.22 - 2026-09-02
### Fixed
* Fixed a form submit that failed at the transport layer settling silently. When the network was down, the connection was refused, or the server was restarting, the request settled with no HTTP status and neither `error.<formId>` nor `error.<formId>.hform` was dispatched, so a handler declared with `data-gina-form-event-on-submit-error` never ran while the form released its submit trigger and reported nothing to the visitor. Such a failure now dispatches both events with `status: 408` and `transportError: true`, the latter distinguishing it from a genuine request timeout. Handlers matching on `status >= 400` keep working unchanged. This code ships in the browser bundle, so consuming bundles need a rebuild as well as a restart.
### Security
* Fixed prototype pollution on the request path. Client-supplied bracket-notation field names such as `__proto__[x]`, `constructor[prototype][x]` and their percent-encoded forms reached an unguarded property assignment in the data helper key-path nesting, and `merge()` copied an own `__proto__` key — the shape `JSON.parse` produces — through its `for...in` loops. Both sources now reject the same three key names — rejecting the key name is what closes this, since an own `__proto__` (the shape `JSON.parse` produces) satisfies an own-property check. The sources were reachable from query strings, urlencoded and JSON request bodies, and multipart text-field names; a polluted prototype could influence outbound request options and safe-method or exemption checks. Note the rejection is by key NAME at any depth of a bracket-notation path, and the field is dropped SILENTLY (throwing on the request-parse path would turn one bad field into a 500): `job[constructor]=x` and a JSON key `{"spec":{"prototype":"v1"}}` previously parsed and no longer do, while a flat top-level field of those names is unaffected. `__proto__` was never a usable field name, but `constructor` and `prototype` are ordinary words — grep your field names and API payloads before upgrading. The affected modules also ship in the browser bundle, so consuming bundles need a rebuild as well as a restart.
